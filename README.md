# 오늘의 진짜 정보판 · 서울 기온

공개 페이지: https://youmjjang.github.io/Real-Information-Board/

서울 좌표의 Open-Meteo 현재 2m 기온을 조회합니다. 실시간 조회와 제출용 이틀 기록, 합성 오류 재생은 서로 독립되어 있습니다.

## 보존된 실제 기록

| KST 날짜 | 기온 | 원천 시각 | 조회 시각 |
|---|---:|---|---|
| 2026-09-11 | 23.9 °C | 2026-09-11T12:30:00+09:00 | 2026-09-11T12:34:09+09:00 |
| 2026-09-12 | 19.2 °C | 2026-09-12T00:15:00+09:00 | 2026-09-12T00:19:45+09:00 |

원천: https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.9780&current=temperature_2m&timezone=Asia%2FSeoul

보존값 차이: 19.2 − 23.9 = −4.7 °C. 서로 다른 시각의 저장값 비교입니다. 9/11 기록은 기존 저장소에 보존된 조회 기록을 유지했고, 9/12 기록은 공개 페이지에서 실제 조회하여 추가했습니다. ALEPH 화면에서 실제 공개 원천 기록이 9/11과 9/12 두 건임을 확인했습니다. ALEPH의 기존 9/11 봉인 payload 상세는 학생 화면에 노출되지 않아 직접 대조하지 못했습니다.

`data/history.json`과 `data.js`에 같은 두 기록을 배포하여 새로운 브라우저에서도 표시됩니다. 새 조회는 브라우저의 별도 일별 저장소를 갱신하며 이 두 기록을 변경하지 않습니다. 사이트 자체는 ALEPH 영수증을 발급하거나 서버 작성 시각을 만들어내지 않습니다.

## 확인 방법

1. 어디로 가나요: 공개 URL 메인 화면을 엽니다.
2. 무엇을 하나요: 이틀 기록 확인 → 실패 버튼 선택 → 다시 시도를 누릅니다. 같은 날·다음 날 저장 확인 버튼으로 중복 방지도 확인할 수 있습니다.
3. 무엇이 보이면 통과인가요: 현재 기온·단위·출처·두 시각·KST, 9/11과 9/12 기록 두 건 및 −4.7°C가 보입니다. 합성 복구 후 120 pt·정상·2건·+15 pt가 보입니다.
4. 안 될 때 무엇이 보이나요: 실패별 원인과 다음 행동, 오래된 값 표시, 마지막 정상값 105 pt와 기존 1건, 다시 시도 버튼이 보입니다.

## AI와 나의 판단

- AI에게 맡긴 일: 화면과 저장·오류·복구 코드 작성, 공식 합성 데이터 검증, 배포와 동작 확인을 맡겼습니다.
- 직접 판단한 일: 서울 기온 하나를 중심으로 구성하고 일반 사용자가 이해하기 쉬운 화면을 선택했습니다.
- AI 제안을 따르지 않은 일: 개발자용 검사 정보를 크게 노출하는 구성을 원하지 않아 상세 정보를 접어서 확인하도록 정리했습니다.

## 구현과 검사

`core.js`는 공식 참조 adapter의 상태 전이를 브라우저와 Node가 함께 쓰도록 감싼 모듈입니다. 실제 조회와 합성 재생 모두 같은 정규화 검증·일별 upsert를 사용합니다. `(signal_id, record_date)`로 동일 날짜를 갱신하고 기존 record ID를 유지합니다. 실제 성공 기록 전체를 localStorage에 한 번에 저장하고 다시 읽어 검증합니다. 저장 불가 상황을 성공으로 표시하지 않습니다.

각 실패 버튼은 합성 상태만 초기화하고 NORMAL-D1-A → NORMAL-D1-B → 선택한 실패를 재생합니다. 다시 시도는 RECOVER-D2를 실제 상태에 적용하여 다음 날짜 한 건을 추가합니다. 원자료·저장값·화면값과 합성 상태 상세를 확인할 수 있습니다.

검사: `node check.cjs`. 공식 9종 fixture와 SHA-256, 동일 날짜 갱신/다음 날짜 추가, 실패별 정상값 보존, 반복 복구 중복 방지, KST 자정, 실제 두 값의 차이를 검사합니다. 공식 원본 자산은 `official/`에 보존됩니다. API 키·외부 라이브러리 설치는 필요 없습니다.

최종 ALEPH 제출과 강사·마스터 승인은 별도 단계이며 로컬 검사 통과가 승인이나 전체 채점 결과를 보장하지 않습니다.
